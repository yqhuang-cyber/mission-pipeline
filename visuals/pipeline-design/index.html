Pipeline 设计

从口语化 script 到可喂给产品的前端组件数据，5 步可中断、可回滚、可 review 的工作流。每步都有 checkpoint，每步都能独立 review。

5 步处理流 5 个checkpoint 2 份主数据 约 55 min 全程 review

详细
1
script_step 1

Script → Phase 框架

Input
mission_x_script_v0.1.md 口语化课程 script，原始输入
Output
mission_x_script_v0.2_phased.md 叠加 phase 切分 + 每 script_step 教学目的
Checkpoint 1

用户 review phase 切分是否合理 + 每 script_step 教学目的是否准确。常见 case：边界 script_step（如"Context Story"归 Phase 1 还是 Phase 2）。

~5 min
2
script_step 2

Phased Script → Component 匹配

Input
v0.2_phased.md phase_component_eligibility.md 前者是 mission 文件，后者是主数据
Output
v0.3_step_component_map.md 每 script_step 选哪个 component + 角色 + 关键字段
Checkpoint 2

用户 review 每个 script_step 选用的 component 是否合适 + 多个 component 共存是否合理。同时校验 Phase ↔ Component 映射表的 enforcement 是否过严/过松。

~5 min
3
script_step 3

Component Map → Content 填充

Input
v0.3_step_component_map.md 原 script
Output
v0.4_component_content.md 每 component lesson_step 的具体 content（display text / audio / image / options...）
Checkpoint 3

用户 review 文案是否符合教学语气 + 选项/答案/期望回答是否合理 + 需要人工补的素材清单。v0.4 的核心单位是 component lesson_step，不是 script_step。

~10 min
4
script_step 4

Content → Lesson Spec

Input
v0.4_component_content.md
Output
v0.5_mission_spec.json 或 .xlsx 最终结构化数据，按产品 schema
Checkpoint 4

校验字段命名与产品 schema 一致 + 必填字段都已填 + 元信息（mission id / title / 词汇 / 时长）齐全。

~5 min
5
script_step 5

喂入产品 → 课程预览

Input
v0.5_mission_spec.json
Output
课程在 web 端完整跑通
Checkpoint 5

实际跑课程的体验：教学节奏是否流畅 + 资产（音频/图片/视频）是否齐全 + component 行为是否符合预期。

~30 min

主数据（跨 mission 复用）

这两份是 pipeline 的"参考书"，不随单个 mission 变，所有 mission 共享。
