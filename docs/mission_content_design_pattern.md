# Mission 内容设计说明

> **给谁看**：教研 · Content Designer（CD）  
> **用来干什么**：统一「一门课长什么样、怎么设计、在系统里怎么走」  
> **不需要先懂**：代码、数据库、字段编号

---

## 开篇：三个问题

做一门 Mission，我们其实在回答三件事：

1. **骨架**：这门课分成哪些段？每一段教什么？  
2. **设计过程**：从课稿到可上课内容，按什么顺序做、每步审什么？  
3. **怎么落地**：在 Pipeline Runner 里对应哪几步、点哪里确认？

下面分三节说明。先建立共同语言，再谈流程。

---

## 1. Mission 内容骨架

### 1.1 一句话

Mission **不是**一串屏幕文案，而是一层层挂好的**教学意图**。  
骨架先定「怎么教」；文案和组件都挂在骨架上。

### 1.2 六层结构（由粗到细）

```
一门课 Mission
  └─ 课段 Phase（固定 4 段）
       └─ 知识教学单元 Knowledge Teaching Unit
            └─ 教学活动 Teaching Activity
                 └─ 组件形态 Component
                      └─ 具体内容 Content（屏幕 + 老师话）
```

| 层级 | 用白话说 | 设计时要想清楚 |
|---|---|---|
| **Mission** | 这一整课 | 学完学生能完成什么交际任务？ |
| **Phase** | 课的大段落 | 现在是进课、发现知识、真实表现，还是收束？ |
| **知识教学单元** | 一段完整的「教一块东西」 | 这一段要建立什么理解或能力？（写清教学目的） |
| **教学活动** | 单元里的「这一下」 | 学生此刻是看、猜、选、跟读，还是说？ |
| **组件** | 这一下用哪种交互画面 | 视频？选择题？跟读卡？造句？角色扮演？ |
| **具体内容** | 画面上的字、选项、Kai 怎么说 | 学生看到什么、听到什么、答错怎么引导？ |

### 1.3 三条铁律（设计时最常踩坑的地方）

1. **一动一器**  
   一个教学活动 = 一件事 = 一种组件 = 产品里的一步。  
   不要在同一步里既讲规律又做综合任务。

2. **三件东西别错位**  
   - **单元**管「学什么」  
   - **活动**管「怎么学这一下」  
   - **组件**管「用什么画面学」  
   单元还在「发现朋友」，活动却做成「整课综合任务」——就是错位。

3. **课段决定气质**  
   引入段重沉浸与任务感；发现段重感知与建构；表现段重综合运用；收束段重回顾。  
   组件要跟课段气质匹配（不是任何组件都能随便放）。

### 1.4 四个课段各自干什么

| 课段 | 学生感受到什么 | 常见单元类型 | 活动大概在干什么 |
|---|---|---|---|
| **P1 引入** | 欢迎进来、看懂情境、知道今天任务 | Welcome · Opening Story · Mission Setup | 打招呼、看开场故事、发布任务 |
| **P2 知识发现** | 一点点发现目标说法 | Context · Connect · Discover · Practice · Pattern · Use | 回放 → 猜含义 → 认词/句型 → 开口练 |
| **P3 真实表现** | 用刚学的完成一件真事 | Mission Ready · Story Replay · 真实任务 | 确认目标、回放检验、完成任务 |
| **P4 收束** | 我学会了什么 | Today You Can · Key Takeaways | 成就感 + 要点回顾 |

**P2 里常用的小循环**（一个单元里可走完，也可拆开多轮）：

> 先感知 → 再懂意思 → 再看形式（词 / 句型）→ 再开口用

### 1.5 和「大纲 / 目录 / 内容」怎么对应

大家口头常说「先写大纲再写目录再填内容」。对应关系是：

| 平时说法 | 在骨架里指什么 |
|---|---|
| 教学大纲 / 课稿 | 口语化 Script（故事、人物、目标说法） |
| 一级目录 | 四个课段 Phase |
| 二级目录 | 知识教学单元 + 每段教学目的 |
| 三级目录 | 教学活动 + 为每个活动选定的组件 |
| 具体内容 | 屏幕文案、选项、Kai 开场 / 触发 / 反馈 / 收尾 |

### 1.6 小例子（帮助建立感觉）

以「发现 朋友」这一类单元为例（示意，非完整课表）：

| 层级 | 例子 |
|---|---|
| 课段 | P2 知识发现 |
| 单元 | Discovery — 朋友（教学目的：理解「朋友」的含义） |
| 活动 1 | 回放「她是我的朋友」→ 组件：视频 |
| 活动 2 | 对比「同学」→ 组件：大图 |
| 活动 3 | 猜「朋友」意思 → 组件：选择题 |
| 活动 4 | 跟读「朋友」→ 组件：听音跟读 |
| 内容 | 每一屏的字、Kai 说的话、对错反馈… |

## 2. 现有内容设计过程

### 2.1 核心思路：意图一层层锁定

我们**不**推荐「一口气写满 40 多屏」。

更稳的做法是：

> 每一层先把**教学意图**说清楚 → 人审过 → 再往下细化。

好处：返工时多半只改一层（比如只改活动拆分），不必整课推翻。

### 2.2 三步流程（建议按这个顺序想）

```
① 大纲定调
   口语课稿：情境、人物、目标语言、任务感
        ↓
② 目录细化（分两小步）
   ②a 切课段 + 写每个单元的教学目的     ← 二级目录
   ②b 拆活动 + 为每个活动选一种组件     ← 三级目录
        ↓
③ 内容填充
   按组件规范写屏幕内容与老师话术 → 可上课、可导出
```

### 2.3 每一步：你产出什么、审什么

#### ① 大纲定调

| | |
|---|---|
| **产出** | 口语化课稿：像一堂完整的课，读得下去 |
| **优先保证** | 情境清楚、目标说法出现自然、任务有吸引力 |
| **这一步先别纠结** | 每一屏按钮文案、选项 ABCD 措辞 |
| **审稿看** | 这门课「像不像一堂课」？核心交际是否立得住？ |

#### ②a 二级目录：课段 + 知识教学单元

| | |
|---|---|
| **产出** | 若干单元，每个有编号/标题，并标在 P1–P4；每单元一句话**教学目的** |
| **审稿看** | 切分是否合理？目的是否准确？边界段归哪一段？（例如：后面再次出现的 Context Story，多半进发现段，而不是引入段） |
| **常见问题** | 一段里塞了两个知识点；教学目的写得太虚（「学习中文」）或太碎 |

#### ②b 三级目录：活动 + 选组件

| | |
|---|---|
| **产出** | 每个单元下的活动链；每个活动只选 **一种** 组件 |
| **审稿看** | 活动链是否服务本单元目的？「学生这一下干什么」和「画面形态」是否匹配？ |
| **匹配直觉** | 猜含义 → 选择；跟读 → 听音跟读；发现句型 → 句型/观察；开口 → 扮演或发音练习 |
| **常见问题** | 连续很多「只看不练」；用同一种组件硬扛所有活动；活动名很漂亮但和所选组件对不上 |

#### ③ 内容填充

| | |
|---|---|
| **产出** | 每一步的屏幕内容 + Kai 开场 /（如有）触发与反馈 / 收尾 + 本步知识点 |
| **原则** | 教学料来自课稿与活动意图；**组件中文名、教学目的原文不要写进 Kai 口播** |
| **步骤短名** | 建议好读、偏英文为主也可：如 `Discover words: 朋友`，方便浏览整课目录 |
| **审稿看** | 学生是否知道此刻要做什么？对了/错了引导是否清楚？本步知识点是否点在真正教的东西上？ |

### 2.4 设计原则（可贴在工位旁）

1. **先骨架后血肉** — 课段、单元、目的没定，不写细文案。  
2. **先动作后画面** — 先想学生这一下干什么，再选组件。  
3. **一动一器** — 一活动一组件一步。  
4. **阶段合乎教法** — 引入 / 发现 / 表现 / 收束各司其职。  
5. **每层可审** — 大纲、目录、内容分开确认，再进入下一层。

### 2.5 做完时，手里大概有什么

| 阶段 | 你手里的东西（可读物） |
|---|---|
| 大纲 | 口语课稿 |
| 二级目录 | 分课段的单元表 + 教学目的 |
| 三级目录 | 每个单元下的活动链 + 所选组件 |
| 内容 | 逐步可预览的课屏与老师话术 |
| 交付 | 结构化课表（可下载、可进产品走读） |

## 3. 在系统里怎么执行（给 CD 的操作视角）

教研过程由 **Pipeline Runner** 按节点帮你推进。  
你不必记文件名；记住：**每做完一层，确认后再进下一层。**

### 3.1 六步对应你在做什么

| 你在 Runner 里 | 对应设计 | 你主要确认什么 |
|---|---|---|
| **准备** | 上传 / 锁定口语课稿 | 课稿是否完整、版本是否对 |
| **Phase 框架** | 切课段、标单元、写教学目的 | 切分与目的是否合理 |
| **Component 映射** | 拆活动、为每个活动选组件 | 活动链与选型是否合理（先选型确认，再审定稿） |
| **Content 填充** | 填屏幕与 Kai 话术 | 内容是否可教、口播是否像老师 |
| **Spec 导出** | 导出课表 | 下载 CSV/XLSX 核对字段与步骤名 |
| **产品喂入** | 进产品走读 | 整课体验是否顺、缺图缺视频再后补 |

### 3.2 和人怎么分工

| 谁 | 负责什么 |
|---|---|
| **系统 / AI** | 给切分建议、活动草稿、字段初稿 |
| **你（CD / 教研）** | 拍板教学意图、改活动、选组件、改文案 |
| **规则校验** | 提醒「这个课段不宜用某种组件」等明显违规 |

**节奏建议**

- 每一大步结束后：**审一遍 → 通过（Approve）→ 再往下**。  
- 活动选型那一步：先为每个活动选好组件并确认，再生成定稿目录。  
- 内容填充阶段：可以边改边**暂存**，改到满意再通过。

### 3.3 导出之后你还要做什么

- 下载课表，重点扫：**课段、单元标题、步骤短名、组件、屏幕文案、Kai 话**。  
- Image / Video 常由后续补资产，空着不一定是错。  
- 进产品走读时，用「学生视角」点一遍：卡壳的地方，多半回到「活动拆分」或「内容填充」改，而不是从课稿重写。

## 附 1：审稿速查（可打印）

**看二级目录时**

- [ ] 每个单元有一句说得清的教学目的吗？  
- [ ] 课段气质对吗？（引入 / 发现 / 表现 / 收束）  
- [ ] 有没有一段里塞了两个不相干的知识点？

**看三级目录时**

- [ ] 每个活动是不是「一件事」？  
- [ ] 活动和组件是否匹配？  
- [ ] 选择题：有要放大的知识点用 CMP-13；直接问理解、题干里没有焦点词，用 CMP-33（不要空着焦点框）  
- [ ] 发现段里是否有足够的「懂意思 → 看形式 → 开口」而不只是连看？

**看具体内容时**

- [ ] Kai 说话像老师吗？（没有念组件名 / 教学目的）  
- [ ] 学生知不知道这一屏要做什么？  
- [ ] 对了 / 错了有没有合适当下的反馈？  
- [ ] 本步知识点是否点在真正教的内容上？
